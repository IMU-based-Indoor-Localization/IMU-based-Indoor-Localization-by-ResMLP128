================================================================================
  IMU 기반 실내 위치추정 (OXIOD + ResMLP) — 개선 시도 전체 보고서
  작성일: 2026-04-13
================================================================================

■ 프로젝트 개요
  - 목표: iOS IMU 센서(가속도계 + 자이로스코프)로 실내 3D 위치 변위 예측
  - 데이터셋: OXIOD (Oxford Inertial Odometry Dataset)
      - 7가지 거치 유형: handheld, handbag, pocket, running, slow_walking, trolley, 기타
      - CSV 파일 기준 총 ~151개 세션
  - 모델: ResMLP 기반 슬라이딩 윈도우 회귀
      - 입력: window_len=100 샘플의 IMU 시계열
      - 출력: Δx, Δy, Δz (3D 변위 벡터)
  - 평가: Euclidean RMSE (m) — 3D 변위 오차, 낮을수록 좋음
  - 기준선 (Zero-prediction):
      - val  ≈ 0.837 m  (모두 0 예측 시)
      - test ≈ 0.848 m

실험 1 — Phase 2 분류기 보조 실험  (runs/exp01, exp02, exp03)
══════════════════════════════════════════════════════════
  날짜: 실험 초기 (4월 11일 이전)
  데이터 분할: 원본 dataset/ 디렉토리 (세션 순서 기반 분할, 편향 존재)

  [exp01] 6ch + PoseClassifier (cls_weight=0.3)
    - 모델: input_ch=6, feature_dim=512, layer_num=6, AdamW lr=1e-3
    - 손실: MSE + CrossEntropy (cls 0.3 비중)
    - 결과: test RMSE = 0.371 m, acc = 0.945

  [exp02] 6ch + PoseClassifier (cls_weight=1.0)
    - 모델: 위와 동일, 분류 손실 비중 증가
    - 결과: test RMSE = 0.385 m, acc = 0.958

  [exp03] 14ch + PoseClassifier + Gaussian NLL — 반복 실험 (12회, 총 ~478 epoch)
    - 모델: input_ch=14, feature_dim=512, layer_num=6, AdamW lr=1e-3
    - 손실: MSE(1~30) → NLL + CrossEntropy (30~)
    - 결과: best val RMSE = 0.296 m, test RMSE = 0.173 m (최고)
    - ※ 주의: 원본 dataset의 val/test는 편향된 분할
              → 동일 세션 타입만 포함되어 실제보다 쉬운 조건
              이 수치는 일반화 성능을 과대평가함

  [결론] 분류기(PoseClassifier) 보조 학습이 회귀 성능을 높이는 효과가 있었으나,
         편향된 데이터 분할로 인해 실제 일반화 성능은 측정 불가.
         → 데이터 분할 문제 해결이 선결과제로 식별됨.

실험 2 — 단순 회귀 베이스라인 재수립  (out/)
══════════════════════════════════════════════════════════
  날짜: 2026-04-11
  데이터 분할: train/ val_dataset/ test_dataset/ (편향 존재)

  설정:
    - 입력: 6ch (user_acc 3ch + rotation_rate 3ch)
    - 모델: feature_dim=512, layer_num=6, AdamW lr=1e-3, dropout=0.2
    - 손실: MSE (1~30 epoch) → Gaussian NLL (31~)
    - 분류기: 없음 (순수 회귀)
    - Epochs: 100 (early stop 20)

  결과:
    - best val RMSE: 0.730 m @ epoch 3
    - 이후 val RMSE 급격히 악화 (epoch 21: 0.786 m → early stop)
    - test RMSE: 0.757 m

  발견된 문제:
    1) Train RMSE 0.37 vs Val RMSE 0.77 → 심각한 과적합
    2) large_scale_floor4 (18파일), iphone_6 (9파일)이 train에만 있음
       → val/test는 이 세션 유형을 전혀 보지 못함 (분포 편향)
    3) 예측 다양성 비율(pred_std / target_std) ≈ 0.55~0.65
       → 부분적 mean prediction collapse (모델이 평균값 주변만 예측)
    4) 방향 오차 분석: angle_mean ≈ 60°, norm_ratio ≈ 0.6
       → 방향 예측과 크기 예측 모두 부정확

실험 3 — 14ch + dropout 강화 (out_phase2/)
══════════════════════════════════════════════════════════
  날짜: 2026-04-12 오전~오후
  데이터 분할: 동일한 편향 분할 (train/, val_dataset/, test_dataset/)

  설정:
    - 입력: 14ch (user_acc + gyro + gravity + attitude sin/cos)
    - 모델: feature_dim=256, layer_num=4, AdamW lr=1e-3, dropout=0.4
    - 손실: MSE만 (mse_epochs=9999, NLL 미사용)
    - warmup: 10 epochs
    - Epochs: 150

  결과:
    - best val RMSE: 0.751 m @ epoch 13
    - 이후 지속 과적합: epoch 73에서 train=0.508, val=0.796
    - test RMSE: 0.765 m (best.pth 기준)

  발견:
    - 14ch가 6ch(0.757)보다 val RMSE 개선: 0.751 m
    - gravity/attitude 채널이 방향 모호성 해소에 기여
    - 그러나 분할 편향 문제 미해결 → 여전히 과적합 패턴 반복
    - early stopping 60 epoch 동안 val이 개선되지 않아 조기 종료

실험 4 — 계층적(Stratified) 데이터 재분할 (out_resplit/)
══════════════════════════════════════════════════════════
  날짜: 2026-04-12 오후
  데이터 분할: dataset_split/ — 새로 생성 (stratified_split.py 사용)

  재분할 방식:
    - 70 / 15 / 15 (train / val / test)
    - placement 유형별 계층화: 각 유형의 파일을 7:1.5:1.5 비율로 분배
    - 결과: train=106, val=23, test=22 파일
    - large_scale_floor4 → val 3개 포함
    - iphone_6 → val 1개, test 3개 포함

  설정:
    - 입력: 14ch
    - 모델: feature_dim=256, layer_num=4, AdamW lr=1e-3
    - 손실: MSE + CosineAnnealing T_max=150

  결과:
    - best val RMSE: 0.766 m @ epoch 13
    - 83 epoch 후 train=0.492, val=0.791 (과적합 지속)
    - test RMSE: 0.814 m

  ★ 핵심 발견:
    - test RMSE가 이전(0.765)보다 나빠진 이유:
      iphone_6 3개 파일이 test에 포함 → 더 어려운(다양한) test셋
    - 반면 per-class 분석:
      handbag/pocket RMSE 개선됨 (재분할 전 0.913 → 재분할 후 0.744)
    - val 분포 균형 회복으로 과적합 조기 발견 가능해짐
    - 그러나 val RMSE 자체가 더 이전보다 낮아지지 않음 → 모델/손실 개선 필요

실험 5 — LLIO 논문 원본 6ch 설정  (out_llio/)
══════════════════════════════════════════════════════════
  날짜: 2026-04-12 야간 (21:48~22:02)
  데이터 분할: dataset_split/ (재분할 사용)

  배경:
    - LLIO 논문(2022): 6ch IMU + ResMLP128로 0.119m 달성 주장
    - 논문 설정을 그대로 재현 시도

  설정:
    - 입력: 6ch (user_acc 3ch + rotation_rate 3ch)
    - 모델: feature_dim=128, layer_num=6, Adam lr=5e-4, dropout=0.2
    - 손실: MSE (1~60) → Gaussian NLL (61~) [2단계 학습]
    - warmup: 5 epochs

  결과:
    - epoch 1~16 내내 train/val RMSE ≈ 0.836 (zero-prediction 수준)
    - 완전히 학습 불가 상태

  ★ 원인 분석 — Augmentation 버그 발견:
    - yaw 회전 augmentation 적용 시:
        수정 전: target[x,y] 회전 O / input user_acc[x,y] 회전 X (버그)
        수정 후: imu_np[0:2] = R2 @ imu_np[0:2] 추가
    - 결과: 수정 후에도 성능 개선 없음

  ★ 근본 원인 — 6ch의 OXIOD 데이터셋 구조적 부적합:
    - OXIOD는 7가지 거치 유형으로 기기 방향(orientation)이 세션마다 크게 다름
      handbag: 기울어짐 / pocket: 뒤집힘 / trolley: 수평 등
    - 6ch에는 gravity / attitude 채널이 없음
      → 모델이 기기의 공간 방향을 알 수 없음
      → 동일한 6ch 패턴이 전혀 다른 world-frame 변위에 대응
      → 일반화 불가능
    - LLIO 논문은 AR 헤드셋(머리 고정, 방향 일정) 데이터 사용
      → 6ch로 충분했던 것은 데이터셋 특성 때문
    - OXIOD처럼 diverse placement에서는 gravity/attitude 없이 6ch만으로 한계

  [진단 실험] 6ch no-augmentation, 20 epoch 학습:
    - train RMSE: 0.842 → 0.768 (학습은 됨)
    - val RMSE: 0.836 → 0.848 (일반화 불가, 오히려 악화)
    → 6ch 모델은 train 세션 암기, val 세션 완전 실패

  [1] 데이터 재분할 (Stratified Split)
      - 문제: 특정 세션 유형이 train에만 존재 → 분포 편향
      - 해결: placement 유형별 계층화 70/15/15 분할 (stratified_split.py)

  [2] 입력 채널 확장 6ch → 14ch
      - 문제: 6ch에서 기기 방향(orientation) 정보 없음
      - 해결: gravity 3ch + attitude(sin/cos 변환) 5ch 추가 = 14ch
      - 효과: 방향 모호성 해소, val RMSE 0.757 → 0.751 개선

  [3] Yaw Augmentation 버그 수정
      - 문제: 6ch augmentation 시 input user_acc 미회전, target만 회전
              → 라벨 노이즈로 학습 불가
      - 해결: dataset.py의 6ch 분기에 imu_np[0:2] = R2 @ imu_np[0:2] 추가
      - 효과: 6ch 학습 가능 상태 복원 (단, 6ch 자체의 한계는 별개)

  [4] 옵티마이저 변경 AdamW → Adam (논문 설정)
      - 문제: weight decay가 소규모 모델에서 과한 정규화
      - 해결: Adam lr=5e-4 (LLIO 논문 설정)
      - 효과: 조합 중 (실험 6에서 검증 중)

  [5] 모델 크기 조정 feature_dim 512 → 128 (논문 설정)
      - 문제: 512 feature_dim이 OXIOD 규모 대비 과도하게 큼
      - 해결: feature_dim=128, 파라미터 수 496K (논문 ResMLP128)
      - 효과: 학습 속도 향상, 과적합 감소 기대

  [6] 2단계 손실 함수 (MSE → Gaussian NLL)
      - 해결: MSE 60 epoch 후 Gaussian NLL 전환
      - 효과: 불확실성 가중 학습으로 어려운 샘플 집중

  [7] PCA 특징 시도 (폐기)
      - 시도: 타겟 변위의 PCA 주성분을 입력 특징으로 추가 (16ch)
      - 실패 원인: 고유벡터 부호 모호성 (±sign 불일치) → 일관성 없는 특징
      - 결과: test RMSE 0.793 (14ch 0.764 대비 악화) → 폐기

  [8] PoseClassifier 보조 학습 (초기 실험에서 유효, 현재 미사용)
      - 시도: placement 유형 분류를 보조 태스크로 학습
      - 원본 데이터셋에서는 유효 (test RMSE 0.173 달성)
      - 단, 편향된 분할이 원인일 가능성 높음
      - 재분할 데이터셋에서 재검증 필요

■ 6ch vs 14ch 구조적 차이 (핵심 인사이트)
────────────────────────────────────────────────────────────────────────────────

  LLIO 논문 6ch 성공 조건:
    - AR 헤드셋 (머리에 고정) → 기기 방향 거의 일정
    - 세션 간 orientation 변화 최소 → gravity/attitude 없어도 학습 가능

  OXIOD 6ch 실패 이유:
    - 7가지 거치 유형 → 세션마다 기기 방향이 크게 다름
    - 6ch 입력(gravity 없음)으로는 orientation 구분 불가
    - 동일한 IMU 패턴이 전혀 다른 세계좌표계 변위를 가리킴
    - 결과: 모델이 train 세션 암기, val 일반화 실패

  OXIOD에서의 필수 채널:
    - gravity(3ch): 수직 방향(절대 기준) 제공 → pitch/roll 모호성 해소
    - attitude(5ch): yaw sin/cos + roll sin/cos + pitch → 수평 방향 기준 제공
    - 최소 권장: 6ch + gravity 3ch = 9ch

■ 데이터셋 구조적 한계 분석

  ┌─ OXIOD 데이터셋 기본 통계 ──────────────────────────────────────────────┐
  │  총 세션 수: ~151개  /  총 녹화 시간: 약 9.2시간  /  샘플링 주파수: 100Hz  │
  │  학습 세션: 106개   /  검증: 23개   /  테스트: 22개  (재분할 기준)        │
  │  Ground Truth: VIO (Visual-Inertial Odometry) — 절대 좌표 아님          │
  └────────────────────────────────────────────────────────────────────────┘

  [1] 거치 유형별 데이터 불균형
  ────────────────────────────
      OXIOD의 7가지 거치 유형은 파일 수가 고르지 않음:
        - handbag:       학습 약 9개  — 적음
        - slow_walking:  학습 약 6개  — 매우 적음
        - handheld:      학습 40개 이상 — 지배적

      결과:
        - 적은 유형(handbag, slow_walking)은 소수 샘플로 일반화 어려움
        - 모델이 handheld 패턴에 편향될 가능성 있음
        - 재분할 후에도 per-class RMSE 차이가 크게 남아 있음

  [2] Y축 분산 비대칭 (y-axis asymmetry)
  ───────────────────────────────────────
      학습 데이터 타겟 분포 분석 결과:
        - target_x 표준편차: σ_x  (기준)
        - target_y 표준편차: σ_y ≈ σ_x × 1.37  (+37% 더 큼)
        - target_z 표준편차: σ_z  (약 절반 수준)

      의미:
        - 실내 보행 경로가 y방향으로 더 길게 분포 (건물 구조 특성)
        - 모델 출력 RMSE에서 y축 오차가 구조적으로 더 크게 나타남
        - 이는 모델 실패가 아닌 데이터 고유 특성임
        - zero-prediction val RMSE ≈ 0.837 자체가 이 비대칭을 반영한 기준값

  [3] Ground Truth 품질 문제
  ─────────────────────────
      OXIOD는 VIO(Visual-Inertial Odometry)를 GT로 사용:
        - 카메라 텍스처가 적은 환경(복도, 단색 벽)에서 drift 발생
        - 긴 세션(30분 이상)에서 누적 오차 존재
        - IMU-only 입력으로 이 drift를 예측해야 하는 모순 존재

      결과:
        - 일부 세션에서 GT 자체가 불안정하여 학습 신호 품질 저하
        - 모델이 실제로 맞는 예측을 해도 VIO drift 때문에 오차로 집계될 수 있음

  [4] 학습-검증 성능 상한선 (ceiling analysis)
  ─────────────────────────────────────────────
      실험 6(out_14ch_128) 기준 gap 추이 분석:
        Epoch  8: train=0.704  val=0.779  gap=0.075
        Epoch 13: train=0.657  val=0.760  gap=0.103
        Epoch 23: train=0.578  val=0.769  gap=0.191

      관찰: gap이 epoch당 약 0.004씩 증가 (선형 누적)

      원인: 학습 세션 수 106개로는 dropout/augmentation으로도 억제 불가
            → 구조적 과적합: 모델이 세션별 특성 암기

      예상 성능 상한선 (OXIOD만 사용):
        - val RMSE:  ~0.70 ~ 0.72 m  (현재 best 0.760 → 개선 여지 제한적)
        - test RMSE: ~0.72 ~ 0.75 m
        - 이 이하는 OXIOD 데이터 규모로는 달성 어려울 것으로 판단

  [5] 데이터 규모 부족
  ─────────────────────
      9.2시간 데이터로 7-class 다양한 환경을 학습하는 것은 근본적 한계:
        - 딥러닝 관성 항법 논문들의 일반적 데이터 규모: 20~500시간
        - RONIN: 100+ 시간, 100+ 명의 피험자
        - TLIO: 12시간, 제어된 환경

      OXIOD 9.2시간으로는 특히 소수 유형(slow_walking=6세션)에서
      충분한 다양성 확보가 불가능함
